## 1. Summary

**The Leads module has not been started.** No funnels, stages, contacts, leads, lists, imports, call queue, dialer, review queue, tasks or reports exist in the schema, API or portal. A search for funnel, lead, stage, playbook, call_queue, dial_attempt, consent_source, import_job, intake and xlsx finds nothing CRM-related. The only "funnel" in the code is the admin sign-up funnel on SA1.

**What exists is reusable groundwork, mostly from D18 click-to-call (ADR 0031):** KYC status, staff-verified caller IDs, the workspace DNC list and platform phone blocklist, per-country legal calling hours in versioned config, a daily cap under a lock, `createPhoneCall` with an agent override and dynamic variables, billing of outbound minutes at the tier rate, and zero billing for unanswered dials. General pieces also carry over: phone and time-zone parsing, the `MintSlot` concurrency reservation, the agent wizard, post-call webhooks, notifications and the digest, `DataTable`, URL filters, CSV export and the transcript and recording player. These account for the 78 PARTIAL rows.

**Two requirements contradict the spec:**

- **Daily dial caps** are 20 / 50 / 150 / 400 per plan (`shared/schemas/src/outbound.ts:85`); §11 says 100 / 500 / 2,000 / 10,000.
- **Calling windows** are held in every time zone of the destination country, never the lead's own zone (`calling-window.ts:21-30`). That is a deliberate, stricter choice in ADR 0031 §4 that §15 does not describe.

**It is blocked as well as unstarted:**

1. **Legal sign-off** for consent wording, calling hours, DNC scrubbing and the recording line (§17 #10). The `outbound_calls` flag stays at 0 % until then.
2. **ADR 0031** allows only callbacks of an existing call. A dialer that calls consented leads needs a new decision.
3. **ADR 0009** confines the LLM to brief → prompt. The post-call extraction and stage decision (§9, Appendix C) need it amended.
4. **All 11 §17 decisions are open,** and there is no CRM ADR.
5. **The spec assumes inbound email parsing exists** "for support tickets" (§6.3). It does not; support tickets come only from the portal form.

**The companion specs in the repo were never synced** (Appendix D). `docs/spec-extract` still reflects portal v0.2 and admin v0.1 for the CRM lines.
